# MineCentral v2 information architecture and navigation

Date: 2026-09-24. Planning specification for [issue #20](https://github.com/Minecentral-Official/Minecentral-Dashboard/issues/20), under [epic #2](https://github.com/Minecentral-Official/Minecentral-Dashboard/issues/2). This document specifies intended behavior; it does not implement routes or redirects.

Inputs: [v2 product requirements](v2-product-requirements.md) (PR-01–PR-17) and the [v1 source inventory](../audits/v1-feature-and-data-inventory.md), baseline `05c4456a230802b1c7b970f4a17e093209753652`. Use the focused beta as the planning baseline; subsequent scope review can enable the reserved capabilities without changing the core hierarchy. The detailed rollout, redirect deployment, backups, and rollback belong to #21.

## Organizing decisions

1. **My Servers** contains private server workspaces and their Stack, Compatibility, Configs, Diagnostics, Upgrades, and Settings sections. A workspace represents intended software/configuration, not a public listing or provisioned server.
2. **Discover** contains public catalog projects. Catalog projects have provenance and versions; adding one requires choosing an owned workspace and version. Public configs and recipes join this area only when implemented.
3. **Tools** is a public explanation/entry point for configuration validation, diagnostics, and upgrade planning. MVP execution happens within an authorized workspace so context, history, and private data remain together. There is no implied anonymous upload service.
4. **Knowledge** contains public curated help and evidence explanations, linked from actual tasks. Private logs/configs never become knowledge articles automatically.
5. **Admin** is a separate, server-authorized operational area. An admin role does not by itself grant unrestricted access to private workspace content; support access requires a separately defined policy.
6. Account, support, and maintained legacy features live in secondary navigation. Existing public listings and resource publishing remain accessible during migration. Empty legacy pages disappear from navigation; existing data is not deleted.

### Stable identity, URLs, and route selection

Use stable opaque workspace IDs so renaming a workspace cannot break config/report links. Every nested object must be verified to belong to both the selected workspace and authorized owner. Catalog detail includes a stable project ID and readable slug; an outdated slug redirects to the current canonical slug only after confirming the object is public. Version IDs must resolve under the stated project. Never merge catalog identities or redirect a legacy resource solely on a similar name.

`/servers/new`, `/discover/plugins`, `/knowledge`, and other static segments are reserved. Legacy listing slugs stay under `/serverlist` and `/dashboard/servers`; they never resolve as workspace IDs. `/account` changes from an alias into the canonical account page; remove its existing redirect when the old dashboard account route starts redirecting to it, avoiding a loop. `/discover` uses a temporary 307 to `/discover/plugins` during the plugin-only phase so it can later become a discovery landing page.

Public catalog filter state uses `q`, repeated `category`, `platform`, `gameVersion`, and `source`, plus `sort`, `page`, and `limit`. Parse against allowed values, omit defaults in generated links, and reset page when filters change. Unknown sort values fall back to the documented default; invalid page/limit values normalize to allowed bounds. Changes are shareable and browser-back restores the filters. Filtered result pages use the unfiltered listing as canonical and are not sitemap entries. Workspace selection and “Add to stack” use an explicit chooser; never add to an arbitrary last-used server automatically.

Private content, pasted logs, YAML, credentials, and serialized form drafts must not appear in URL parameters. A task may carry a project/version ID or tool identifier in temporary navigation context, but authorization is rechecked on continuation. Only normalized same-origin relative return paths are accepted at sign-in; reject external/protocol-relative URLs and auth-loop destinations. GET navigation, including post-login return, never performs a mutation.

### Workspace navigation

Desktop: retain global navigation, with an owner-only workspace switcher and rail ordered **Overview → Stack → Compatibility → Configs → Diagnostics → Upgrades → Settings**. Show server name and intended platform/version above the rail. The switcher lists authorized workspace names with disambiguating metadata and a Create workspace entry. Switching workspaces opens the corresponding top-level section when it exists, otherwise Overview; it never reuses a nested config/session ID from the previous workspace.

Mobile: keep a compact workspace name/switcher header and a labeled “Workspace sections” sheet containing the same ordered destinations. Global bottom navigation stays visible with sufficient content/safe-area padding; it must not cover editor controls, submit buttons, or error messages. Keep the current section title and breadcrumb above content, so the global My Servers selection is not mistaken for the section selection. A later Agent/Connection item is hidden until enabled.

Breadcrumbs follow **My Servers → server name → section → item**. Config history adds the revision label; diagnostic and upgrade reports show their creation time to distinguish saved results. Public breadcrumbs follow **Discover → Plugins → project → version**, or **Knowledge → article**. Do not include private workspace names in public page metadata or shared discovery links.

### Navigation states and interaction rules

| State                            | Required desktop and mobile behavior                                                                                                                                                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Active item                      | Use segment-aware matching and `aria-current`; Overview is exact-only, a detail selects its containing section, and only the most specific child is active. Query filters do not alter the active section                                         |
| First run / no workspaces        | My Servers explains the workflow and offers Create workspace; tool/add-to-stack entry offers creation and then resumes the non-mutating task                                                                                                      |
| Empty section                    | Explain what belongs here and show one relevant action; do not display fabricated counts or healthy status when no evaluation exists                                                                                                              |
| Loading                          | Preserve navigation/title and stable skeleton space; indicate pending content without briefly rendering “not found” or zero counters                                                                                                              |
| Failure                          | Keep navigation usable, distinguish load/save failure, retain unsaved text where feasible, and provide retry; do not silently navigate away after failed save                                                                                     |
| Unsaved edits                    | Internal navigation, switcher, and mobile sheet selection offer Stay or Discard; Save and continue is available only if validation/save succeeds. Use browser unload protection where supported, without promising crash recovery                 |
| Expired sign-in                  | Require reauthentication and preserve only a safe destination/task reference; do not put config/log drafts in return URLs or silently publish/submit them after login                                                                             |
| Unauthorized/missing object      | Guest private-page requests go to sign-in; authenticated users get a generic not-found for another owner's/missing object. Non-admin admin requests receive access denied with a My Servers link; API/actions enforce authorization independently |
| Deleted/retained historical data | Authorized archived records state their status and allowed actions; deleted/missing private objects use generic not-found. Historical reports do not silently point at a different evaluation                                                     |
| Unsupported or later feature     | Hide launch controls and navigation; disabled later routes return 404. Existing unsupported legacy resource data remains reachable through its maintained routes                                                                                  |
| Mobile sheet / account menu      | Trigger has an accessible name and expanded state; focus enters the modal, stays within it, Escape/backdrop closes it, and focus returns to the trigger. Close on navigation; no hover-only links                                                 |
| Keyboard and zoom                | Skip-to-content link, visible focus, semantic navigation labels, readable text labels alongside icons, and scrollable menus/editor; content remains operable at narrow/zoomed widths                                                              |

Changing tabs/sections uses browser history so Back returns to the previous task. Selecting a filter can replace intermediate history entries while committed searches create navigable state; the final filter state must always be reflected in the URL. Support ordinary links/open-in-new-tab; don't require a previously mounted dashboard to open a deep link.

## Legacy migration policy

This is the intended first-v2-cutover contract, not a list of redirects to deploy immediately. Keep the current behavior until the target capability, data mapping, and authorization are available. #21 must sequence rollout and prove rollback before switching traffic.

- **Remain:** keep the URL and its purpose; fix the defects identified by the audit as part of the relevant implementation work. Public records retain their existing visibility; private drafts are never made public by migration.
- **Redirect 308:** permanent GET/page alias after the target is ready. Preserve only allowlisted destination query parameters, never credentials/old toast payloads. Resolve directly to the final destination without chains/loops.
- **Retire 410:** a known empty legacy page has no equivalent product. Remove its navigation and serve a useful gone page with a relevant optional link, rather than silently redirecting unrelated content. Do not delete records because a placeholder route disappears.
- **Remain API:** retain the existing endpoint and request shape during consumer migration; enforce correct authorization/status behavior. Do not redirect POSTs to UI routes or replace JSON responses with sign-in HTML. Versioned replacement API design is outside #20.

Legacy plugin detail pages remain distinct from canonical imported catalog pages in the first cutover. Their files, IDs, likes, publishing workflow, and URLs remain supported. Where a verified catalog mapping exists, add a related catalog link; do not automatically canonicalize two different representations. No name-only redirects. The public `/plugins` directory also remains as a legacy browse surface reachable through the footer/legacy pages, while primary Discover opens `/discover/plugins`.

Tools pages should explain what the tool does before requiring sign-in. If no workspace exists, create one and return to the intended section; if the workspace was deleted or access changed, show the chooser again. Canceling a chooser returns to the starting page. Configuration and diagnostic drafts remain private even if the owner navigates to public discovery.

## Indexing, authorization, and compatibility requirements

Index only intentionally published catalog, legacy resource/listing, and curated knowledge pages. Private workspace/account/support/admin pages and sign-in are noindex and excluded from sitemaps; that indexing policy is not a substitute for authorization. Later published configs/recipes get independent public URLs and release snapshots, never direct private-workspace links. Public titles, link previews, and errors must not reveal private object metadata.

Retired public placeholders return 410; nonexistent or unpublished public objects return 404. Authenticated aliases may redirect to their protected destination without exposing object data. Existing APIs return JSON errors appropriate to their contract, and upload/auth callbacks retain protocol-specific behavior. Do not apply generic page redirect middleware across APIs. Public legacy slugs and imported catalog slugs are different namespaces, and changing navigation does not grant permission to merge their data.

The destination routes and redirects must ship as an atomic, verified change per route family: ensure the target works, remove reverse aliases, then enable redirects. Permanent redirects can be cached; #21 must account for that in rollback. Keep a route manifest and migration fixture list so static route names cannot accidentally be treated as dynamic IDs. No redirect in this document permits deleting source records or storage.

## Implementation handoff and acceptance scenarios

Route/nav implementation remains in the relevant epic issues (#3–#17); #20 delivers the map. #21 owns deployment sequence and reversibility; #22 owns detailed personas/journeys. Suggested navigation work can reuse the existing [active-path helper](../../src/components/sidebars/sidebar-active.util.ts), [shared layouts](../../src/components/layouts), and [UI primitives](../../src/components/ui), after applying this hierarchy and permissions. Do not preserve empty destinations merely because a shared menu currently lists them.

Before navigation ships, verify:

1. A guest can browse Discover, Tools, and Knowledge on desktop and mobile; sign-in returns to the intended safe page without performing an action.
2. An owner with zero, one, and multiple workspaces can create/select a workspace; each nested object is accessible by deep link only to the authorized owner. Switching from one workspace's config detail does not load the same config ID in another workspace.
3. The same section is active in desktop rail/mobile chooser; Overview is not active on every descendant. Browser Back, keyboard focus, and sheet close behavior work consistently.
4. Invalid YAML/unsaved content is not silently discarded by section changes, switching workspaces, or moving to public discovery. Loading/failure states preserve navigation and do not display invented health/counts.
5. Every legacy route below its new policy returns the specified page/redirect/error, with no loops, unauthorized draft disclosure, or broken callback POSTs. In particular, /account and /dashboard/account do not redirect to each other.
